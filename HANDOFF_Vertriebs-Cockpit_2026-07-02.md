## 3. System-/Datenmodell (WICHTIG — Grundlage für alles)
- **Odoo = das EINZIGE lebende WaWi.** Seit ~19.06.2026 laufen alle Zu-/Abgänge über Odoo.
  Datei „LosSerie (stock.lot)". **Verkaufsstatus: Verfügbar · Angeboten · Reserviert · Verkauft.**
  ⚠️ Spaltenlayout wechselt zwischen Exporten (30/34/39 Spalten) → Parser mappt über Spalten-**NAMEN**, nie Index. **Immer nur EINE (die neueste) Odoo-Datei laden.**
- **JTL + Portal = zwei ABGELÖSTE, EINGEFRORENE WaWis** (kein Zu-/Abgang mehr).
  - Portal `ALL_SOLD` = komplettes historisches Verkaufsarchiv (~31k, Jan–Jun 2026, alle mit Lager-Nr).
  - Portal `Stock-Analysis` = alter Restbestand (~271, meist Status „A").
  - `JTL Export` = alte Aufträge/Zahlungsdaten.
- **AMM = das PHYSISCHE Lager** (Datei `BESTAND134_*.CSV`), WaWi-unabhängig.
  **Status: QE = im Lager · VS = Versand · AA = Ausgang/Auslieferung** (empirisch belegt: VS/AA nur Verkaufte). Enthält **WE-Datum = echtes Wareneingangsdatum**. **Keine Preise (EK/VK)!**
- **AMM AUFTRAG_STATUS** = Ausgangs-Pipeline (QU/AK/SU je Auftrag), keine Lager-Nr.
- **Universeller Schlüssel = Lager-Nr (900…)**, über alle Systeme eindeutig. Alle Merges/Validierungen laufen darüber.
- **Lagerdauer:** NUR aus AMM `WE-Datum` (0…1524 Tage). Odoo `Pool-Eintritt` wird bei Migration zurückgesetzt (alles 0–8 Tage) → für Alter UNBRAUCHBAR.
